# Managing Python with uv

[uv](https://docs.astral.sh/uv/) manages the Python environment and
dependencies used by this project.

In this repository, uv is responsible for:

- Creating the local `.venv` environment.
- Reading project and dependency declarations from `pyproject.toml`.
- Resolving exact package versions into `uv.lock`.
- Installing the project and its selected dependency groups.
- Running commands inside the managed environment.

The [official uv project guide](https://docs.astral.sh/uv/guides/projects/)
provides a broader introduction to these concepts.

## Installing uv

Follow the [official installation instructions](https://docs.astral.sh/uv/getting-started/installation/)
for the appropriate operating system. Confirm that uv is available with:

```bash
uv --version
```

This repository already contains a configured `pyproject.toml`, so do not run
`uv init` after cloning it.

## Project files

Two version-controlled files describe the environment:

| File | Purpose | Edited by |
| --- | --- | --- |
| `pyproject.toml` | Declares supported Python versions, direct dependencies, dependency groups, packaging, and tool settings | Contributors and uv commands |
| `uv.lock` | Records the exact resolved package versions used to reproduce the environment | uv |

Commit both files whenever a dependency change updates them. Do not edit
`uv.lock` manually. The local `.venv/` directory is generated by uv and must
not be committed to Git. See the official explanation of
[project files and environments](https://docs.astral.sh/uv/concepts/projects/layout/).

## Creating the development environment

From the repository root, run:

```bash
uv sync
```

This creates `.venv/`, installs Dermapred as an editable package, and installs
the default `dev` dependency group. In this project, `dev` includes the test,
lint, type-checking, and documentation groups.

Training dependencies are deliberately separate. Include them when working on
the data or model pipeline:

```bash
uv sync --group train
```

To install only the published runtime dependencies, without the default
development tools, use:

```bash
uv sync --no-default-groups
```

The available selection options are described in the
[locking and syncing guide](https://docs.astral.sh/uv/concepts/projects/sync/).

## Running commands

Prefix project commands with `uv run` so they use the managed environment:

```bash
uv run pytest
uv run ruff check .
uv run mypy
uv run mkdocs serve
```

`uv run` checks that the lockfile and environment are current before executing
the command. Activating `.venv` manually is therefore optional. See
[running commands in projects](https://docs.astral.sh/uv/guides/projects/#running-commands)
for more examples.

## Dependency categories

Dependencies are separated according to who needs them:

| Location in `pyproject.toml` | Purpose | Example |
| --- | --- | --- |
| `[project].dependencies` | Required when users install Dermapred | PyTorch, NumPy, Pillow |
| `[project.optional-dependencies]` | Published features users may choose to install | A future browser or desktop UI |
| `[dependency-groups].train` | Local data and model-development tools | DVC, MedMNIST |
| `[dependency-groups].test` | Automated testing | pytest |
| `[dependency-groups].lint` | Code-quality checks | Ruff |
| `[dependency-groups].type` | Static type checking | mypy |
| `[dependency-groups].docs` | Documentation generation | MkDocs |
| `[dependency-groups].dev` | Combined groups used for normal development | Test, lint, type, and docs |

Published dependencies and local dependency groups serve different purposes.
The [uv dependency documentation](https://docs.astral.sh/uv/concepts/projects/dependencies/)
describes this distinction in detail.

## Adding and removing dependencies

Use uv commands instead of installing packages directly into `.venv`.

Add a runtime dependency required by Dermapred users:

```bash
uv add <package>
```

Add a repository-only training dependency:

```bash
uv add --group train <package>
```

Add a test dependency:

```bash
uv add --group test <package>
```

Remove a dependency from the corresponding group:

```bash
uv remove --group train <package>
```

These commands update `pyproject.toml`, `uv.lock`, and the local environment.
Review both version-controlled files before committing the change.

## Locking and reproducibility

Create or refresh the lockfile explicitly with:

```bash
uv lock
```

Check that it still agrees with `pyproject.toml` without changing it:

```bash
uv lock --check
```

Continuous integration should reject an outdated or missing lockfile rather
than silently resolving a new environment:

```bash
uv sync --locked
uv run --locked pytest
```

The lockfile does not update merely because newer packages are published. To
request dependency updates deliberately, use:

```bash
uv lock --upgrade
uv lock --upgrade-package <package>
```

Always review and test dependency upgrades before committing the resulting
lockfile.

## Exporting for other tools

`uv.lock` is the source of exact dependency versions for this repository. If
an external platform requires a `requirements.txt` file, generate one rather
than maintaining a second dependency list manually:

```bash
uv export --format requirements.txt --output-file requirements.txt
```

See the official [export documentation](https://docs.astral.sh/uv/concepts/projects/sync/#exporting-the-lockfile)
for other supported formats.
